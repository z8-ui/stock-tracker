# S3-3C：板块估值与资金流前端展示修复

阶段：S3-3 的最后一个子阶段。只改前端，后端契约、Provider、缓存逻辑全部未动。

## 1. 字段证据（来自本机真实缓存 `_data_cache.json` 的 496 条）

`/api/sector-valuation` 的 data 行，键集合 **恰好** 是：

```
['change', 'market_cap', 'name', 'pb', 'pe']
```

| 字段 | 真实情况 | 来源 |
|---|---|---|
| `pe` | 496/496 有值；负 PE 90 个；PE=0 0 个 | 东财 `f9`（Provider 已按 /100 处理） |
| `pb` | **496/496 全部 null** | 东财 `f23` 实测返回 `"-"`，Provider 转 None（不是 0） |
| `market_cap` | 496/496 有值，34.95 ~ 187,960.13（亿元） | 东财 `f20`（元），Provider `round(f20/1e8, 2)` |
| `change` | 496/496 | 东财 `f3` |

结论：**市值字段真实存在且可靠**，PB 在现有上游口径下全部缺失。
因此气泡图改为 PE × 市值，并把 PB 缺失明确写成"暂无数据"，不再画 PB=0 的假纵轴。

`rangeText(meta, shown)` 只认元数据：

| 元数据 | 文案 |
|---|---|

## 7. r3 整改（第二次复审后）

### 7.1 必改 1：PE=0 在对数轴上根本画不出来

对数轴无法表示 0，原实现把 PE=0 系列挂在 `xAxisIndex=0`（log），
真实 ECharts 下它的 x 坐标是 `-Infinity`，但说明文字仍写"已绘制 N/N"。

修法（不动数据、不改 0 为 0.01、不用 abs）：
- PE=0 走**独立 grid + 类目轴**（`type:'category'`, data `['PE=0']`），
  这是真实有限坐标，不是假值；tooltip 显示 `PE: 0（PE=0，非盈利也不亏损）`。
- 只有存在 PE=0 时才创建第三个 grid；真实 496 行没有 PE=0，页面结构不退化（仍 2 grid）。
- `bubblePoints()` 增加 `undrawn`，缺 PE / 缺市值单独计数，不混进"已绘制"。

用项目自带 ECharts 5.5.1 在 Node 里跑生产 option 构造器（SSR + convertToPixel）实测：

```
正 PE 20  → [346.79, 276.00]
PE=0      → [737.98, 395.04]   （不是 -Infinity）
负 PE -20 → [640.98, 203.55]
496 行    → 逐点 convertToPixel，496/496 有限，0 个 NaN
```

浏览器里另外注入 1 行合成 PE=0 验证：3 个 grid、`zeroCoord=[521.77, 395.72]`、
"已绘制 497/497"、右下区域可见灰点（截图见 evidence）。

### 7.2 必改 2：网络异常未处理、估值页无法重试

原来只处理了"接口返回了 JSON 但 code≠200"，`fetch()` reject / `json()` reject 全是未处理拒绝，
估值页还会把 `window._sectorLoaded` 永久置 true。

修法：
- `sector_view.loadSectorData()`：统一取数，**Promise 永不 reject**，
  把失败分成 `network / parse / code` 三类交给 `onError`。
- `sector_view.sectorLoader()`：首次失败解除占位（可重试）；成功后 `load()` 直接跳过（防重复）；
  `load(true)` 用于定时刷新；已有数据时刷新失败只提示、不清数据。
- `static/js/valuation.js`：改用 loader，失败文案 `⚠ 请求失败，当前无可用数据（网络连接失败）。 可在切换 Tab 后重试。`
- 热力图加载逻辑从模板内联抽到 `static/js/heatmap.js`（生产代码可直接被 Node 执行），
  刷新失败文案 `⚠ 本次刷新失败，当前保留此前页面数据（网络连接失败）。`，treemap/排行保持不动。

真实浏览器验证（真的把 Flask 停掉）：

```
首次失败 : ⚠ 请求失败，当前无可用数据（网络连接失败）。   console []
重试     : 重启 Flask 后再点 Tab → 已绘制 496/496           console []
热力图   : 停服刷新 → "本次刷新失败，当前保留此前页面数据（网络连接失败）。"
           charts kept {"treemap":true,"rank":20}；重启后恢复 496/496   console []
```

## 8. r4 整改：定时自动刷新被加载器跳过

### 8.1 问题

模板注册是 `startAutoRefresh('heatmap', loadHeatmapData)`，而 `setInterval` 调用回调时不传参，
于是每个 15 秒周期都走 `loader.load(false)` → `state.loaded && !force` → 直接 `skipped`。
表现为：页面写着"15 秒自动刷新"，实际只有首次加载发了请求。

### 8.2 修法（最小改动）

```js
document.addEventListener('DOMContentLoaded', function () {
    loadHeatmapData();                 // 首次：普通模式，成功后不重复请求
    startAutoRefresh('heatmap', function () { return loadHeatmapData(true); });
});
```

`loadHeatmapData(force)` → `loader.load(!!force)`：首次加载、手动刷新、定时刷新共用同一条链路，
`inFlight` 复用保证不会并发打请求，也不需要新的重试机制。

### 8.3 定时器链路测试（新增 tests/frontend/test_sector_timer.js）

真实执行 `static/js/app.js`（startAutoRefresh）、`static/js/heatmap.js`（loadHeatmapData），
并把 `templates/heatmap.html` 里的注册片段**从文件里抽出来执行**；定时器是受控 `setInterval`，
不等 15 秒。20 条断言：

```
首次加载                  fetch=1  treemap=1  bars=2   间隔=15000ms
三个定时回调              fetch=4  treemap=4  bars=8   （不再 skipped）
成功→失败→恢复            fetch=5 → 提示"保留此前页面数据"，旧图不清 → fetch=6 恢复渲染
加载中再触发定时回调      fetch 仍为 1（复用 in-flight），完成后仍可刷新
无未处理 Promise rejection
```

### 8.4 真实浏览器（真的停 Flask）
