## 3. 五个必答问题的结论

### 3.1 问题一：`total=496` 却只回 60 行

**明确结论**

1. `pn` = 页码（1 起）、`pz` = 每页条数（服务端上限 **100**）、`po=1` = 按 `fid` 降序、`np=1` = `diff` 返回数组。
2. **60 条不是"全部板块"，只是第 1 页**：`total=496` 是完整板块数（9 页 `pz=60` 或 5 页 `pz=100` 取满，唯一 496，无重复）。
3. 代码里**不存在任何翻页请求**（`pn` 恒为 `"1"`，全局 `_get` 无循环）→ 现状**必然**只能看 60 个。
4. `total` 与"本次返回行数"是两个字段，当前代码完全没读 `total`，因此**无处发现差异**。
5. **页面展示范围**：`/api/heatmap` 返回的 `data` 严格等于"第 1 页 60 行"，页面标题"行业板块热力图 / 涨跌幅排行 / 资金流入排行"没有任何"前 60"字样（`templates/heatmap.html:42-60`，`dashboard.html:60-68` 取 top10 更无标注）。**结论：当前是"把 60 个当全部展示"，必须修。**

**三个可选方案（带代价，需评审选一个）**

| 方案 | 做法 | 上游请求 | 页面呈现 | 风险 |
|---|---|---|---|---|
| **A（推荐）全量抓取** | Provider 内循环 `pn=1..5, pz=100`，按 `f12` 去重合并；任一分页失败 → `partial` + `missing_pages` | 5 次（~1.1s），缓存 60s → 峰值 ~5 req/min | 接口给 496；treemap 全量、排行图前端取 Top N（需前端小改，见 §8.4） | 首次加载多 4 次请求；分页期间行情跳动会导致个别板块跨页重复/遗漏（用 `f12` 去重 + `notes` 记录差额） |
| **B 保持 60，明确标注** | 不改抓取，只把范围写进接口与页面："前 60 / 共 496（按涨跌幅）" | 1 次 | 页面出现明确范围提示 | 用户永远看不到其余 436 个板块；"热力图"名不副实 |
| **C 折中** | `pz=100` 单页（前 100），标注"前 100 / 共 496" | 1 次 | 100 条 | 仍是截断，只是截得少 |

**我的建议：A**。理由：`total` 已证明是完整集合；5 次请求 ~1.1s + 60s 缓存，成本可接受；且 A 能同时满足"不把 60 当 496"和"板块排行有意义"。若评审认为首屏延迟不可接受，可退化到 **A + 懒加载**（首屏 100，前端点"加载全部"再取剩余 4 页）——但那需要改前端和路由参数，属第二阶段。

### 3.2 问题二：PB 缺失与 PE 语义

**四态定义（对外 `pb`/`pe` 只允许 4 种取值，禁止第五种）**

| 场景 | 上游原值 | 对外值 | 判定 |
|---|---|---|---|
| 真实有值 | `1.85` | `1.85` | 数值 |
| 真实零 | `0` / `0.0` | `0.0` | 数值（**不得**当缺失） |
| 明确无值 | `"-"` | `null` | 缺失 |
| 字段不存在 | `key` 不存在 | `null` | 缺失 |
| 不可解析 | `"abc"` / `""` | **抛 `ProviderFormatError`** | 结构异常（不静默变 null，也不变 0） |

**PB 现实**：496/496 为 `"-"` → 迁移后**每个板块 `pb=null`**。这不是"过滤"，是如实反映上游。
**必须同步处理的前端后果**：`app.js:476-503` 气泡图以 `pb` 为 Y 轴，`pb=null` 后**所有点消失**（现在是全挤在 `y=0` 的"假数据点"）。二选一：
- **B1**：气泡图改为"PB 缺失 → 显示占位文案『板块 PB 暂无数据（东财 clist 未提供）』"，PE 维度改用"PE 排行 + 市值气泡"两图（推荐，语义正确）；
- **B2**：不动前端 → 图表空白（用户会以为坏了）。不推荐。

**PE 四态**：`f9` 实测 496 个全为数值：90 个负、0 个 0、0 个 `"-"`。
- `pe > 0`：正常显示。
- `pe < 0`：**保留**，`notes` 记 `negative_pe: 90`；PE 排行图把负 PE 单独一段（或降序时排在最后并标注"亏损"），不做数值截断、不取绝对值。
- `pe == 0`：保留为 `0.0`，不进"亏损"集合（0 与负是不同语义）。
- `pe = null`：不参与排序，UI 显示 `--`。
- **默认返回全集**（496），过滤交给展示层并显示"N 个亏损板块"。若评审要求接口保持"只给正 PE"（兼容旧前端），则另一路：接口加参数 `include_loss=1` 默认 0 → 但这就是"兼容旧错误口径"，我不建议。

### 3.3 问题三：list 缓存元数据

**约束**：业务 `data` 保持 list；元数据在外层；旧 list 缓存必须能读。

**设计（不实施 S3-7A 信封）**

1. 缓存**存储格式不变**：`_data_cache.json["sector_flow"] = [ {...}, ... ]`（裸 list）→ 旧缓存原样可读，S3-7A 到来时再整体升级。
2. 新增**旁路元数据**：`_cached_get()` 增加可选 `meta_sink: dict`，在真正返回数据的分支写入
   `{"served": ..., "fetched_at": ..., "rows": len(data), "total": 上游 total, "missing_pages": [...]}`，**不写进缓存本体**。
3. 新增 `sector_meta(key)` 返回统一外层信封（供路由使用）：

```
{
  "asof": "2026-11-10 15:00:00" | null,     # 数据自身时间（板块接口无时间戳 → 用最近成功抓取时刻，且 must 标 asof_source="fetch"）
  "asof_source": "fetch" | "unknown",
  "fetched_at": 1762...,                    # epoch，本地抓取时刻
  "is_stale": false,
  "status": "success" | "partial" | "empty" | "failed" | "degraded" | "stale",
  "rows": 496,
  "total": 496,
  "range": {"shown": 496, "total": 496, "truncated": false},
  "missing": ["pages:5"],                   # 失败的分页/缺失字段
  "notes": ["negative_pe:90", "pb_unavailable:496"],
  "source": "eastmoney_clist",
  "served_from": "memory|network|file|file_fallback|none"
}
```

4. **asof 的诚实口径**：板块 `clist` 报文**没有时间戳字段**（S3-0 已确认，S3-2 也复核过），因此 `asof` 只能是"最近一次成功抓取时刻"，必须带 `asof_source="fetch"`，**不得**伪装成交易所时间。盘中 `asof` 与真实数据时刻的偏差 ≤ 缓存 TTL。
5. `cache_meta("sector_flow")` 保留（`routes.py` 与既有测试在用），内部改为委托 `sector_meta()`，返回字段超集，向后兼容。

### 3.4 问题四：状态维度（不能挤进一个 status）

**六个词分属三个维度**，本设计明确拆开：

| 维度 | 字段 | 取值 | 谁产生 |
|---|---|---|---|
| 请求结果 | `fetch_status` | `success` / `failed` | Provider + HTTP 层 |
| 数据完整度 | `completeness` | `complete` / `partial` / `empty` | 解析层（行数 vs `total`、分页失败、字段缺失） |
| 数据新鲜度 | `freshness` | `live` / `stale` / `degraded` | 缓存层（是否回退旧数据） |

`status` 只作为**对外聚合展示**（供前端一个开关判断），聚合规则固定如下，**不允许其它组合**：

| 场景编号 | 上游 | 缓存 | `fetch_status` | `completeness` | `freshness` | 聚合 `status` | API 表现 |
|---|---|---|---|---|---|---|---|
| S1 | 成功、行数=total | 写回 | success | complete | live | `success` | `200` + 496 行 + `truncated:false` |
| S2 | 成功、部分页失败 | 写回（部分） | success | partial | live | `partial` | `200` + 已抓到行 + `missing:["pages:5"]` |
| S3 | 成功、`data=null`/空数组 | **不写回** | success | empty | live | `empty` | `200` + `data:[]` + `msg:"暂无板块数据"`（**不是** 500 静默） |
| S4 | 结构异常（`rc≠0`、`diff` 类型错） | 不写回 | failed | — | — | `failed` | `502` + `data:null` + 原因 |
| S5 | 失败，但有旧缓存（未过期） | 命中 | failed | complete（旧） | stale | `stale` | `200` + 旧 496 行 + `is_stale:true` + `asof` 旧时间 |
| S6 | 失败，有旧缓存但已过期 | 回退 | failed | complete（旧） | degraded | `degraded` | `200` + 旧行 + `is_stale:true` + `degraded_reason` |
| S7 | 失败，无缓存 | — | failed | — | — | `failed` | `502`/`500` + `data:null`（沿用现有 500 文案） |

- **S3 与 S7 必须能区分**："接口成功但今天真没有数据"≠"接口挂了"。
- 旧代码把 S2/S3/S4/S7 全变成 `[]` 或 `None`（`except: pass` + `if not result`），这是本阶段要消灭的核心。
- `status` 之外的三个维度必须都出现在外层信封；`status` 只是聚合值，**不得**作为唯一信息源。

### 3.5 问题五：缓存策略（两个接口分开）

| 维度 | 板块资金流（`sector_flow`） | 板块估值（`sector_valuation`） | 依据 |
|---|---|---|---|
| 缓存键 | `sector_flow`（不变） | `sector_valuation`（**新增**，此前无缓存） | — |
| 盘中 TTL | **60s** | **300s** | 资金流是分钟级变量，5 页抓取成本高但 60s 足够；PE/PB 是日频基本面，5 分钟粒度已过剩 |
| 休市策略 | 直接读文件缓存，不再打上游（收盘后板块数据不变） | 同（且允许 24h 内复用） | 与 `get_stock_quote` 的休市策略一致 |
| 文件缓存过期判定 | 盘中 > `STALE_AFTER_SEC` 判 stale；休市 > 3 天判 stale | 同 | 沿用 `cache_meta()` 现有阈值，不新造口径 |
| 上游失败降级 | 有缓存 → `stale`/`degraded` 回退并标 `served_from=file_fallback` | 同 | 对齐 S3-1 第四轮语义 |
| `fetched_at` | 命中缓存**不刷新**，保留原始抓取时间 | 同 | S3-1 结论复用 |
| 数据时间戳 | 接口无时间戳 → `asof=最近成功抓取时刻`，`asof_source="fetch"` | 同 | §3.3 |
| 并发 | 复用 `_cached_get` 的 single-flight；**同一 cache_key 只允许一个请求在抓 5 页** | 同 | 防止页面多标签同时打 5×N 次 |

**为什么两者 TTL 不同**：资金流分时变化、且是页面主视图；估值是日频，300s 足够。**不为统一而统一**（评审要求原话）。

## 4. Provider 设计

### 4.1 文件与形态

```
services/data/providers/eastmoney_sector.py     # 新增，单 Provider 双模式
```

```
class EastmoneySectorProvider(Provider):
    name = "eastmoney_sector"
    kind = "sector"
    MODES = ("flow", "valuation")
```

- 不新建第二个 Provider，不新增业务服务层。
- 两个模式**共用**：URL、UA/Referer、分页循环、`diff` 形态兼容、错误分类；**各自独立**：`fields` 参数、行映射、缺失统计。
- 绝不复用 `eastmoney_flow.py` 的 klines 解析（那是"逐日 CSV"，与 `clist` 的"对象数组"不同，混用会"看着对、数全错"，S2 已踩过）。

### 4.2 契约

```
fetch(mode="flow", pages=None, page_size=100) -> ProviderResult
  request(): 循环 pn=1..，直到"取满 total"或"返回 0 行"或 pages 上限(默认 10)，
             逐页 JSON 解析后交 normalize 合并；任何一页失败记入 extra.missing_pages
  normalize(raw_pages): -> (rows, asof, extra)
             rows:    list[dict]  业务结构，字段与现 API **完全一致**
             asof:    ""          接口无时间戳，恒为空串（由缓存层用抓取时刻补齐）
             extra:   {"total": 496, "fetched": 496, "missing_pages": [], "notes": [...],
                       "negative_pe": 90, "pb_unavailable": 496}
```

**flow 模式行结构（与现 API 逐字段一致）**

```
{"name": str, "change": float, "flow": float}
```

**valuation 模式行结构（与现 API 逐字段一致）**

```
{"name": str, "pe": float|null, "pb": float|null, "change": float, "market_cap": float}
```

- 新增键只在**外层信封**（§3.3），业务 list 不加键 → 前端 `s.xxx` 读取不受影响。
- `f12`（板块代码）**只用于内部去重与日志**，不进入业务 list（若评审希望暴露 `code`，需明确批准，因为那会改变 list 元素结构）。

### 4.3 解析规则（逐字段，防"缺失变 0"）

| 上游 | `flow` 模式 | `valuation` 模式 |
|---|---|---|
| `f14` 名称 | `str(row.get("f14") or "").strip()`；空 → 跳过该行并计入 `notes.skipped_no_name` | 同 |
| `f3` 涨跌幅 | `num()`：`"-"`/`None`/`""` → `None` → **该行 `change=null`**（不再 0.0） | 同 |
| `f62` 净流入（元） | `num()` → `/1e8` → `round(2)`；缺失 → `null` | — |
| `f9` PE | — | `num()`：`"-"`/缺失 → `null`；负数保留；0 保留 |
| `f23` PB | — | 同上 → 实测全 `null` |
| `f20` 总市值（元） | — | `num()` → `/1e8` → `round(2)`；缺失 → `null` |
| `f25`/`f37` | 不使用 | 不使用（语义未确认） |
| `diff` 形态 | list 或 dict 两种都接受；其它类型 → `ProviderFormatError` | 同 |
| `rc != 0` 或 `data is None` | `ProviderEmpty`（空）或 `ProviderFormatError`（结构异常），**分情况** | 同 |
| 未知数值字符串 | 抛 `ProviderFormatError`（不静默 null / 不静默 0） | 同 |

`num()` 与现有 `_num()` 的**唯一差别**：`"-"` 不再是 0，而是 `None`。这条必须有专门测试，否则 TD-16 会以另一种形式复发。

### 4.4 ProviderResult 扩展（最小、向后兼容）

`services/data/base.py` 现只有 `data/source/status/asof/fetched_at/is_stale/error/elapsed_ms`。
本阶段新增三个**带默认值**的字段：`missing: list = []`、`notes: list = []`、`extra: dict = {}`；
`normalize()` 允许返回 `(data, asof)` 或 `(data, asof, extra)`（旧 Provider 不改也能跑）。
`fetch()` 的 status 判定从"只看空/非空"扩展为：`extra.missing_pages` 非空 → `partial`。

> 风险：`base.py` 被 3 个既有 Provider 继承（tencent / eastmoney_flow / 未来的 sector）。
> 改动全部是"新增带默认值的字段 + 兼容 2 元组返回"，**不改既有分支行为**；S3-1 的 58 例必须全绿后才允许继续。

### 8.3 与既有测试的冲突（必须提前说明）

`tests/test_data_service.py:43-47` `test_loss_sector_skipped` 断言"负 PE 板块被跳过" —— 这是 **S3-3 要改掉的旧口径**。
