> `docs/V2.1_S3_TECH_DEBT.md`。基准 HEAD `48d3e68`，502 例全通过。

## 0. 判定词（全文只用这五个）

| 词 | 含义 | 允许的下一步 |
|---|---|---|
| **PASS** | 本阶段所有必改项通过，证据齐全 | 进入下一阶段 |
| **PASS-with-must-fix** | 主链路通过，有 ≤5 条必改项 | 修完复审，不进入下一阶段 |
| **FAIL** | 存在数据正确性错误或门禁不满足 | 回滚或修复后重跑 |
| **BLOCKED** | 环境/依赖/上游缺失导致无法判定（不是代码失败） | 补环境或补证据 |
| **NOT TESTED** | 明确未执行，且已登记 | 必须写进交付报告的"未测试清单" |

**禁止**：把 NOT TESTED 写成 PASS；把"我看了代码觉得没问题"写成 PASS。

## 1. 通用门禁（每个阶段都必须同时满足）

| # | 门禁 | 判定方式 | 不满足时 |
|---|---|---|---|
| G1 | 全量测试 **只增不减且全绿** | `python -m unittest discover -s tests -v`；例数 ≥ 上一阶段（S3-1 后为 591） | FAIL |
| G2 | 旧测试预期 **零修改** | `git diff` 中不得出现既有 `assert*` 的期望值改动 | FAIL |
| G3 | 真实报文差分 **差异项 = 0** | 同一夹具分别喂新旧实现，逐键比对；差异必须打印而非口头声明 | FAIL |
| G4 | 真实请求 **每接口仅 1 次** | 采集脚本日志：URL、时间、HTTP 状态、字节数、sha256 | BLOCKED |
| G5 | 改动范围 **不越界** | `git diff --stat` 只含本阶段"涉及文件"清单内的文件 | FAIL |
| G6 | 页面回归 **真实浏览器** | 迁移前后各一次：API JSON 数值对照 + 截图（1440×900）+ DOM 关键文本 | NOT TESTED（不得写 PASS） |
| G7 | 无伪数据路径 | 代码中无默认 0/空数组/编造日期/mock 兜底进入生产分支 | FAIL |
| G8 | Git 纪律 | 单阶段单 commit；无 `push --force` / `reset --hard` / `clean`；`git status` 除声明文件外干净 | FAIL |
| G9 | 回滚可执行 | `git revert <commit>` 后服务能起、页面能开、测试全绿（实际演练一次） | BLOCKED |
| G10 | 证据可复算 | 交付包内含 manifest + 原始日志 + 离线自验脚本，第三方无需 pip 即可复算 | PASS-with-must-fix |

## 3. 证据包要求（沿用 S2 方法）

每次阶段交付必须包含：

```
01-code/        代码包（zip）+ 对应 Git bundle
02-manifest/    逐文件 SHA256（可 sha256sum -c）
03-tests/       原始 unittest 日志（不修改）+ 差分结果 + 上游请求日志
04-git/         git dump（rev-parse / log / status / diff --stat / 本阶段完整 diff）
05-pages/       迁移前后 API 原始 JSON + 截图 + 采集时间/数据日期/运行环境
06-docs/        阶段报告（做了什么/没做什么/为什么）+ 未测试清单
SHA256SUMS.txt
```

**硬要求**：

1. 原始测试日志不可改；解释差异（如行数 vs 例数）时必须给出机制，不许"以结果为准"。
2. API 数据必须区分：真实网络实测 / 夹具回放 / Mock 测试——三者不得混写。
3. 截图必须带：时间、数据日期、viewport、浏览器版本；不得用旧截图冒充。
4. 判"通过"的操作必须能被**一个人用一条命令**复算。

## 4. 回滚验收（每阶段必做）

```bash
git revert --no-edit <该阶段commit>
python -m unittest discover -s tests      # 必须回到上一阶段例数且全绿
# 启动服务 → 打开 /  /market-flow  /stock-flow  /valuation  /heatmap
```

通过标准：服务能起、4 个页面无 500、测试全绿、`data/events.db` 未被改动（mtime 不变）。

S3-7 额外要求：回滚前先 `cp _data_cache.json _data_cache.json.bak`，
回滚后验证旧格式能被读（不是"删缓存重抓"）。

## 5. 不得做出的声明（对应 S2 的教训）

| 不得声明 | 除非 |
|---|---|
| "浏览器已验证" | 有截图 + 采集时间 + viewport + 浏览器版本 |
| "审查方已独立重跑 502 项" | 对方的依赖环境真的装了 flask 并给出 `Ran 502` |
| "差分 0" | 打印了逐键比对结果，且夹具是真实报文 |
| "接口没变" | 有迁移前后原始 JSON 对照（不是"字段名一样"） |
| "已修复 S2-KI-1" | 8 条用例通过 + 缺指数时 API 返回 `partial/missing` |
| "无副作用" | 有 `git diff --stat` 且只含白名单文件 |

## 6. 放行 / 拒绝判定表

| 情形 | 判定 |
|---|---|
| 全部门禁通过，必改 0 条 | PASS，进入下一阶段 |
| 主链路通过，必改 ≤5 条（不涉数据正确性） | PASS-with-must-fix |
| 任一数据正确性问题（伪值、缺指数仍 success、单位错、日期错） | FAIL |
| 测试例数下降 / 旧断言被改 | FAIL |
| 真实报文缺失导致无法差分 | BLOCKED |
| 上游接口当天不可用 | BLOCKED（不得用旧报文假装当天采集） |
| 页面未做真实浏览器回归 | NOT TESTED（不得 PASS） |

## 7. S3 整体放行条件

1. S3-1…S3-7 全部 PASS 或 PASS-with-must-fix 且必改清零；
2. A 类债务 15 条全部关闭（其中 TD-05 为跨阶段累计清零，要求 `grep -c "except:" data_service.py` = 0），B 类 5 条保持"可接受"并有页面/文档标注；
3. 全量测试 ≥ 502 且全绿，新增用例覆盖：真实报文回放、失败语义、缓存兼容、
   `partial/missing`、`days` 隔离、降级可见；
4. 六个页面入口（`/`、`/market-flow`、`/stock-flow`、`/valuation`、`/heatmap`、`/ai`）
   在真实浏览器下无 500；
5. 交付包按 §3 结构完整，`sha256sum -c` 全通过，bundle 可独立 clone；
6. 未测试项清单为空，或每条都有明确的"为什么不测 + 风险"。
