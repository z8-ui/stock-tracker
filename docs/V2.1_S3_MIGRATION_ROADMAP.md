## 1. 排序原则

1. **先证据后迁移**：每个数据源在改代码前，先各发 1 次真实请求存夹具（S2 的教训：
   没有真实报文，差分就退化成"自己和自己比"）。
2. **收益 = 风险降低 × 复用次数**，不是"Provider 数量"。
   复用次数 ≥ 2 或 存在"伪数据/静默失败"风险的模块优先。
3. **一次一个模块**：迁移 + 测试 + 页面回归 + 提交，然后才下一个。
4. **依赖优先**：S3-1（行情解析/缓存）是 S3-2 的前置；S3-3 独立；
   **S3-7A（缓存信封）必须早于 S3-3**（list 元数据是 S3-3 的验收前提）；
   **S3-7B（键集中/降级/S2-KI-1）保持最后**（跨模块）。
5. **每阶段 ≤ 3 个生产文件**，diff 可读；不出现"顺手重构"。
