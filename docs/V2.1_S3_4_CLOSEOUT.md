## 3. S3-4 交付了什么

### 3.1 F10 Provider（S3-4A）

- 请求、市场后缀、十字段解析从 `data_service.get_latest_financials()` 迁到
  `services/data/providers/eastmoney_f10.py::EastMoneyF10Provider`；
- 市场后缀统一由 `normalizers.stock_market()/stock_secucode()` 决定，北交所先于深市判定；
- `REPORT_DATE` 强制校验，`NOTICE_DATE` 缺失允许成功并返回 `None`（与旧实现的 `""` 差异已记录）；
- 原始 `null` 保持 `None`、真实 `0` 保持 `0`，不 round、不转亿元；
- `NaN / Infinity / -Infinity / 1e309` 一律 `ProviderFormatError`，错误带原始字段名；
- `success / empty / failed` 在 Provider 层区分，不再 `except: return None`。

### 3.2 F10 缓存（S3-4A）

- 6 小时 TTL、`refresh=True` 穿透语义保留；
- 文件缓存与内存缓存都过 `_fin_values_finite()`（七字段）；
- 异常缓存**按层**淘汰：`_drop_fin_memory()` / `_drop_fin_file()`，不误删另一层有效财报；
- 恢复请求有界：一次业务调用最多一次额外上游请求，`file_fallback` 坏值只淘汰不重试；
- 休市时合法内存可作为降级回退（`_asof` 保留原始时间、`_stale=True`、`_fallback=memory`）。

### 3.3 状态与页面（S3-4B）

- 请求级状态对象（不是模块级最新值）：
  `fetch_status / served_from / freshness / fetched_at / report_date / cache_rejected / reason`；
- `trace` 由调用方持有，`get_latest_financials(..., trace=...)` 在 `finally` 写 `trace["status"]`；
- 后台 SWR 通过 thread-local 隔离，不再篡改前台已确定的状态；
- `/api/valuation`、`/api/intrinsic-value` 各自透传独立的 `financials_status`，旧字段一律不变；
- `financials` 仍是十字段 dict 或 `null`，状态绝不塞进财报本体；
- 页面区分：实时抓取 / 缓存 / 旧数据（降级，且 empty 与 failed 文案分开）/ 暂无财报 /
  获取失败 / 缓存无效 / 状态未知；报告期与本地抓取时间分开展示。
