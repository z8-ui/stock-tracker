### 3.1 非有限数值（r2 修正）

`NaN` / `Infinity` / `-Infinity` / 溢出（`"1e309"`，解析成 `inf`）不是财务数据。
一旦放行，会形成"财报成功 → `available=True` → 内在价值 `inf` / 偏离度 `nan`"，
而且 `json.dumps(..., allow_nan=False)` 会直接抛
`ValueError: Out of range float values are not JSON compliant`。

处理：`_num_field()` 对 `int/float` 与字符串解析结果都做 `math.isfinite()` 检查，
非有限 → `ProviderFormatError`，消息带 `field=EPSJB` 这样的原始字段名。
**不改成 0，不给默认值，不丢弃字段后继续。**

| 输入 | 结果 |
|---|---|
| `EPSJB="NaN"` / `"Infinity"` / `"-Infinity"` / `"1e309"` | failed，`field=EPSJB 不是有限数值` |
| `EPSJB=float("nan")` / `float("inf")` | failed，同上 |
| `TOTALOPERATEREVE` / `PARENTNETPROFIT` / `BPS` / `ROEJQ` 非有限 | failed，消息带各自字段名 |
| `EPSJB=0` | success，`0`（int） |
| `EPSJB=None` | success，`None` |
| `EPSJB=51.53`、`BPS=216.949629787912` | success，数值与类型不变 |
- `"-"` / `"--"` / `""` / `"null"` 这类占位符 → `None`（东财偶尔用 `-` 表示缺失）；不可解析的字符串 → `failed`，不静默变 None。

## 4. 状态语义

| 情形 | Provider 结果 | 业务返回值（`get_latest_financials`） |
|---|---|---|
| HTTP 200 + JSON + `result.data` 非空 + `data[0]` 是对象 + 日期可解析 | `success` | 十字段 dict |
| 个别指标为 null（如 EPS=null） | `success` | 十字段 dict，该项为 None |
| `result.data = []` | `empty` | `None`（不缓存） |
| `result.data = null` | `empty`（上游明确"无记录"） | `None`（不缓存） |
| `result` 缺失 / 非对象 | `failed` | `None`（不缓存） |
| `result.data` 非列表 / `data[0]` 非对象 | `failed` | `None`（不缓存） |
| `success=false`（上游报错） | `failed` | `None`（不缓存） |
| HTTP 非 200 | `failed`（`HTTP 500` 等） | `None` |
| 超时 / 连接失败 | `failed`（`ProviderTimeout` / `ProviderNetworkError`） | `None` |
| JSON 非法 | `failed`（`JSON 解析失败`） | `None` |
| `REPORT_DATE` 缺失 / 非法日期 | `failed`（消息含 `field=REPORT_DATE`） | `None` |
| 数值字段不可解析（如 `EPSJB="abc"`） | `failed`（消息含 `field=EPSJB`） | `None` |
| 数值字段非有限（NaN / Infinity / 溢出） | `failed`（消息含 `field=EPSJB`） | `None` |
| `NOTICE_DATE` = null / `""` / `"-"` / `"--"` | `success`，`notice_date=None` | 十字段 dict |
| `NOTICE_DATE` 非空但非法（如 `2026-13-01`） | `failed`（消息含 `field=NOTICE_DATE`） | `None` |

关于「empty 和 failed 都是 None」：**这是刻意的**。旧契约里业务方只认 dict 或 None，
把状态塞进十字段 dict（例如 `{"status": "empty"}`）会被估值代码当财报读。
状态在 Provider 层完整保留（`ProviderResult.status` / `.error`），页面呈现方案见 §9。

## 10. S3-4B 页面状态呈现建议（本轮未实施）

现状：`static/js/valuation.js::buildFinancialsHtml()` 在 `fin` 为 falsy 时 `return ''`，
所以"无财报"和"接口失败"在页面上都是**一片空白**，无法区分，也不满足阶段验收的
"无财报时显示无财报，而不是暂无数据"。

建议方案（不改 `financials` 本体）：

1. **状态走独立字段，不塞进财报对象**

   `/api/valuation` 的 `data` 里增加：

   ```
   "financials_status": "ok" | "empty" | "failed" | "stale",
   "financials_note":   "东财 F10 无 2026 三季报记录" / "财报接口暂不可用（超时）" / ""
   ```

   `chart["financials"]` 结构保持十字段或 null 不变。前端 `buildFinancialsHtml(fin, status, note)`
   在 `fin` 为空时按 status 输出"无财报"或"财报暂不可用"，两者文案不同、颜色不同。

2. **状态从哪来**：`data_service` 内新增 `get_latest_financials_status(stock_code)`（或让
   `get_stock_valuation` 内部同时读 Provider 状态），把 `ProviderResult.status` 映射成
   `ok / empty / failed`；`served_from=file_fallback` 时映射成 `stale`。
   老函数 `get_latest_financials()` 的返回值一个字不改。

3. **对原契约的影响**：新增字段，不删不改；旧前端忽略未知字段即可，不破坏。

4. **预计改动文件**（S3-4B 需要单独授权）：
   - `data_service.py`：状态侧通道 + `get_stock_valuation` 透传
   - `routes.py`：`/api/valuation` 增加两个字段（`/api/intrinsic-value` 可选）
   - `static/js/valuation.js`：`buildFinancialsHtml` 接收状态与文案
   - `templates/valuation.html`：可能只需一个容器 id（若走 DOM 插入则无需改）

## 12. 剩余风险

1. `result.data=null` 被判为 `empty` 而不是 `failed`：东财在 `pageNumber` 越界时确实返回 `null`，
   与"没有财报"在响应里无法进一步区分；若上游改成"出错也返回 null"，会被误判成 empty。
   缓解：`success=false` 已单独判 failed；真正出错通常带 `success:false` 或非 200。
2. 日期字段从"宽松切片"改为"必须是合法日期"：`REPORT_DATE` 为空或异常字符串现在直接 failed
   （以前会得到空串继续跑）。这是有意的（结构错误不静默吞），但会让旧缓存路径下的兜底更常用。
3. **有意语义修正**：`NOTICE_DATE` 缺失时，旧实现返回 `""`，新实现返回 `None`。
   两者都是"没有披露日期"，但 `None` 与本项目其它缺失值一致。因此"所有缺失输入的返回值与旧实现
   逐字节相同"这句话**不成立**，别这样对外描述；正常有值时的逐字段一致性不受影响（10/10）。
4. `NOTICE_DATE` 非空但非法仍然 failed：本轮只放宽"缺失"，没有放宽"写错"。
5. 解析耗时增加了 `isfinite` 与类型校验，微秒级，可忽略。
6. 缓存 TTL 未变（6 小时），财报披露当天最长可能滞后 6 小时 —— 与迁移前一致，不属于本轮问题。
7. 真实上游验证只覆盖 3 只股票、单次调用（2026-11-12 19:19 由 Hermes 采集），不能证明长期稳定性；
   本轮 r2 修正全部是离线可复现的，没有重新请求上游。

## 13. r3 修正：历史缓存的数值真实性闸门

### 13.1 问题

Provider 的 `math.isfinite()` 只作用于**本次网络抓取**。`_cached_get()` 的三条读取路径
（交易时段内存命中、休市读文件、刷新失败回退文件）都不再经过 `normalize()`，
`validate_fn=lambda x: x is not None` 也拦不住 `eps=inf`。实测（真实加载 9bb82f0 的 data_service.py）：

```
修复前  缓存eps=inf     返回eps=inf     available=True  intrinsic=inf  严格JSON=ValueError 上游调用=0 缓存残留=True
修复前  缓存eps=nan     返回eps=nan     available=False intrinsic=None 严格JSON=ValueError 上游调用=0 缓存残留=True
修复前  缓存eps=51.53   返回eps=51.53   available=True  intrinsic=1374.14 严格JSON=OK      上游调用=0 缓存残留=True
```

### 13.2 处理（只在 F10 范围内，不动全局 `_cached_get`）

1. **出缓存再验一次**：`_fin_values_finite(fin)` 检查 `eps/bps/revenue/revenue_yoy/
   net_profit/profit_yoy/roe` 七个数值字段 —— `None` 或有限数值才通过，`bool`/`str`/
   NaN/Infinity 一律判无效。0 仍是合法值。
2. **同一校验也传给 `_cached_get(validate_fn=...)`**：新抓取结果与后台 SWR 刷新结果都会过这一关，
   坏数据不会被写进缓存。
3. **就地淘汰 + 有界重抓**：命中坏缓存时 `_drop_fin_cache(code)` 只删 `fin_{code}`
   （内存 / `_LAST_SUCCESS` / 文件里的该 key；不清空整份 `_data_cache.json`、不动其它 key 与板块元数据），
   然后 `force=True` 重抓**一次**。重抓成功 → 正常十字段；重抓仍失败 → 返回 `None`，
   绝不把坏值当 `file_fallback` 兜底。
4. **诊断侧通道**：`_FIN_LAST_DIAG[code] = {status, reason, cache_rejected}`，
   由 `get_financials_diagnostic(code)` 读取，供 S3-4B 页面状态呈现；不改变 `get_latest_financials()` 契约。

修复后同脚本：

```
修复后  缓存eps=inf     返回eps=None    available=False intrinsic=None 严格JSON=OK 上游调用=2 缓存残留=False
修复后  缓存eps=nan     返回eps=None    available=False intrinsic=None 严格JSON=OK 上游调用=2 缓存残留=False
修复后  缓存eps=51.53   返回eps=51.53   available=True  intrinsic=1374.14 严格JSON=OK 上游调用=0 缓存残留=True
```

（"上游调用=2"是因为脚本连续取了两次财报，每次各重抓一次；单次调用只重抓一次。）

### 13.3 新增测试（I 组，12 条）

| 测试 | 断言 |
|---|---|
| 文件缓存 `eps=inf` | 返回 None；上游被调用一次；坏条目从文件里消失 |

| 坏缓存 + 重抓失败 | 返回 None；文件里不残留坏条目；估值不出现 nan/inf |

全量：**827/827 OK**（739 基线 + 88 F10），干净 Clone 同结果。

### 13.4 剩余风险

- 坏缓存是"每次取数淘汰一次 + 重抓一次"的局部策略：如果上游持续返回坏数据，
  每次请求都会多一次上游调用（有界，不会无限循环）。真正的源头已被 Provider 拦住。
- 文件缓存被淘汰后，若重抓失败，该股票在本次请求内**没有**旧财报可展示 ——
  这是有意选择（宁可不给，也不给非法值）。
