# 外部审查协议（REVIEW_PROTOCOL v1）

> 用途：把"外部 AI 审查"从自由对话变成固定接口，减少返工、避免结论含糊。
> 适用：任何一轮交付前的独立复审（不只 GPT，换模型也照用）。
> 配套：`docs/REVIEW_CHECKLIST.md`（复发问题清单，随轮次增长）。

---

## 0. 一句话原则

**审查者只做两件事：判定达标与否、指出具体错误。**
方案设计、实现、真实数据核对由执行方负责；接口语义以真实报文为准，任何人都不能凭记忆定义数据源行为。

---

## 1. 执行方每轮提供的 6 段固定输入

| # | 段 | 内容要求 |
|---|---|---|
| 1 | 本轮范围 | 做了什么 + **明确未做什么**（防越界，也防审查者扩大战线） |
| 2 | 改动清单 | 文件级 `+/-` 行数、`diff --stat`；关键 hunk 单独贴 |
| 3 | 证据表 | 每条结论 → 证据类型（真实报文 / 执行输出 / 静态检查）→ 强度（强 / 中 / 仅约定） |
| 4 | 测试 | `unittest` **实际执行**数、PASS/FAIL/ERROR/BLOCKED；关键单文件的实际执行数 |
| 5 | 复算命令 | 一条命令能重现的：`python3 -m unittest discover -s tests`、`sha256sum`、真实请求 URL+参数+采集时间 |
| 6 | 自我怀疑 + 选择题 | 3~5 条"我可能漏了什么" + 3~5 个必须二选一/多选一的问题 |

第 6 段是重点：把自己怀疑的漏点先摆出来，比让对方复述任务省时间，也更容易被挑出真错。

---

## 2. 审查方必须按 4 段固定输出

| 段 | 内容 |
|---|---|
| A. 判定 | `PASS` / `PASS-with-must-fix` / `FAIL` / `BLOCKED`，必须选一个，不接受"看起来没问题" |
| B. 必改项 | **最多 5 条**；每条格式：`文件:行` → 问题 → 为什么必须改 → 验收方式 |
| C. 可选建议 | 显式标"不阻塞"，不得与必改项混排 |
| D. 下一轮门槛 | 满足哪几条才允许进入下一步 |

---

## 3. 挑错清单（审查时逐条过）

1. **空值 / 伪零**：`null` 是否在 JS（`Math.abs`、`|| 0`）或后端（默认值）被吃成 0
2. **缓存失效**：口径改了，旧缓存是否继续供错值（需版本标记或失效路径）
3. **异常吞掉**：`except: pass`、`if not text` 是否又把失败变成空数据
4. **单位与字段**：金额/占比是否混用；跨接口口径是否一致（元 vs 亿、% vs 元）
5. **旧测试兼容**：是否靠修改既有期望"制造通过"（禁止）
6. **结构契约**：返回字段增删是否破坏页面/图表
7. **安全**：密钥、`config_local.py`、本地数据库、缓存文件是否可能进发布包
8. **文档一致性**：`VERIFIED/PARTIAL` 与证据是否匹配；文档内部（§x 与 §y）是否互相矛盾
9. **声明与实测一致**：报告里的数字能否被一条命令复算
10. **边界覆盖**：缺失 / 全零 / 全缺 / 部分缺 / 多源聚合，是否各有用例

---

## 4. 对审查方的硬性约束

1. 结论必须可验证：指出文件/行/命令，不接受"建议再检查一下"。
2. 一个必改项只对应一个问题，不许三件事打包成一条。
3. 不许要求修改既有测试期望来达到通过。
4. 不许把公开字段字典当权威证据，最高只能算"约定级"旁证。
5. 不确定时给**两个方案 + 各自代价**，不要硬选一个让人猜。
6. 必改项超过 5 条时只保留前 5，其余降级为可选建议。
7. 同一问题再次出现时必须明说"这是复发"，执行方据此写入检查清单。

---

## 5. 升级机制

同一问题出现 ≥2 次 → 写入 `docs/REVIEW_CHECKLIST.md`，此后不再讨论该问题本身，
只核对"这条是否被执行"。目标：清单只增不重，返工逐轮下降。

---

## 6. 反面案例（来自真实轮次，作为协议的存在理由）

| 现象 | 后果 | 现在由哪条拦住 |
|---|---|---|
| 只凭"请求里 fields2 的顺序"推断列含义 | 换序请求证明假设是错的，差点把 Provider 建在错误顺序上 | §3-9 + §1-3（证据强度分级） |
| 后端把 `None` 做对，前端 `Math.abs(null)→0` 又把空值画成 0 | 页面显示"真实的 0.00 亿" | §3-1 |
| 改了字段口径但没处理旧缓存 | 上线后页面继续显示错值（-279 亿） | §3-2 |
| 文档 §2.5 已更新，§6 还写着"未完成" | 审查者按过期描述给结论 | §3-8 |
| 用 AST 统计的函数数当"测试数" | 数量口径失真 | §1-4（只认实际执行数） |
