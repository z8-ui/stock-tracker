## 1. 结论先说

- `data_service.py` 现有 **1388 行 / 41 个顶层函数**（S1 盘点时是 1335 行 / 38 个，本轮收尾新增 `_bump` / `cache_stats` / `provider_stats` 三个遥测函数；**S2 把三个资金函数搬进 Provider 后为 1364 行 / 41 个（实测 wc -l）**），实际承担 **6 类职责**，不是 1 个：传输、解析、缓存、可观测、交易时段、业务/装配。
- 数据源只有两家：**腾讯**（行情快照、历史 K 线）与 **东方财富**（资金流、板块、F10、行业 PE、搜索），另有"模拟兜底"开关（`ALLOW_MOCK_FALLBACK=False`，默认关闭）。
- 真正的耦合点不是"文件大"，而是：**7 处直连 `requests.get` 绕过统一传输、超时口径 5/6/8/10 四套、`_get()` 把异常吞成 `None` 后无法区分"超时/空/格式错"**。
- 本轮只搬了 **腾讯行情快照** 这一个数据源（`services/data/providers/tencent.py`），行为逐字节等价（差分测试 6 组），页面数据不变（浏览器实测）。
- 盘点里顺带发现并修掉两个"假数据"问题：`get_market_flow` 全零伪装成真实行情、交易日兜底成"今天"。二者都在 S1 的"不得伪造成功/不得凭空生成"要求内。

## 5. Provider 规范（本轮落地）

`services/data/`

```
base.py          Provider（模板方法 fetch）、ProviderResult、6 种状态
exceptions.py    ProviderError → Timeout / NetworkError / FormatError / Empty / Unavailable
normalizers.py   to_float / to_int / split_tencent_snapshot / parse_trade_time / market_prefix
registry.py      register / get / names / describe / call / call_chain
providers/tencent.py   TencentQuoteProvider（本轮试点）
```

**契约**

- 子类只实现 `request()`（发请求，失败抛异常类型）与 `normalize()`（原始响应 → `(data, asof)`）。
- `fetch()` 负责计时、异常 → 状态转换、`elapsed_ms`，**永远不抛异常**给调用方。
- `ProviderResult`：`data / source / status / asof / fetched_at / is_stale / error / elapsed_ms / attempts`。
- 状态：`success / empty / partial / stale / failed / unavailable`；
  `stale` 只由缓存层产生（Provider 恒 `False`），避免两层各自判断新鲜度。
- `asof` 只来自源本身；源没给就空串，**不用"现在"顶替**。
- Provider 不做业务判断：价格有效性（`price>0`）仍留在 `get_stock_quote`，因为那是"这只股票能不能算有效行情"，不是"这个源返回了什么"。
- `call_chain(["a","b"], ...)` 按序降级，返回命中结果，并在 `attempts` 里留下每个源的状态（谁超时、谁空数据一目了然）。

**刻意不做**：连接池、自动重试、缓存、并发编排。这些要么属于上层（缓存），要么现在没有第二个源可编排（重试风暴只会放大故障）。

## 7. 试点迁移：腾讯行情快照

**为什么选它**

1. 它是全系统最底层的行情入口：`get_stock_quote`、`get_market_flow`（大盘指数）、`get_stock_real_money_flow`（借 `get_stock_quote` 取成交额）都经过它 —— 搬一个能覆盖三条链路。
2. 逻辑最薄：一次 GET + `~` 切分 + 字段数校验，不含缓存与业务判断，能直接检验 Provider 规范是否够用。
3. 有清晰可复现的失败面：超时、连接失败、空报文、字段截断 —— 正好对应四类异常。

**改动**

| 位置 | 改动 |
|---|---|
| `services/data/**`（新增 7 文件） | Provider 规范 + 腾讯行情实现 + 注册表 |
| `data_service._tencent_quote` | 13 行 → 3 行委托：`registry.call("tencent_quote", code)`，失败仍返回 `None` |
| `data_service.get_stock_quote` | 未改（字段与单位换算保持原样） |
| `data_service.get_market_flow` | 只删"全零兜底"与"今天兜底"两处假数据，其余未改 |

**行为等价证据**

- 差分测试：正常 88 字段 / 刚好 51 字段 / 截断 50 字段 / 空串 / 无 `~` / 单个 `~` 六组输入，
  旧实现（原样抄进测试的参照函数）与新实现返回值**逐字节相等**；
  三种异常（Timeout / ConnectionError / RuntimeError）下两者都返回 `None`。
- 真实接口：`/api/stock-quote?code=600519` → 贵州茅台 1453.0、PE 22.11、成交额 62.0 亿、成交量 42848 手。
- 浏览器实测（Chrome 153 headless，1440×1000）：
  `/market-flow` → `3649.18 上证指数 2026-11-06 -1.10%`、`-524.97 亿 明显流出`、canvas=2；
  `/valuation` → 贵州茅台 PE 22.11、canvas=4；两页均无 `undefined` / `NaN`。
  数值与迁移前一轮完全一致。

## 9. S2 建议（下一阶段）

**对象：东财资金流（`get_stock_money_flow` + `get_stock_real_money_flow`）**

理由：
1. 两个函数解析同一种 `klines` 报文，单位换算各写一遍 —— 合并成一个 `EastMoneyFlowProvider` 能直接消掉重复（问题 #6）。
2. `get_market_flow` 也拉东财大盘资金，同域可复用同一 Provider 的传输与解析工具。
3. 现有 `test_routes_offline` 已经有 `flow_payload()` 夹具与"字段不足 / 空 / 坏 JSON"分支，回归成本低。
4. 搬完后资金类接口可以开始用 `call_chain(["eastmoney_flow", "tencent_flow"])` 做真正的双源降级，补齐本轮 NOT TESTED 项。

步骤与验收：
1. 先写 `providers/eastmoney_flow.py`，只做"请求 + 解析成 {dates, flows, unit}"，用现有夹具做差分；
2. `data_service` 两个函数改薄委托，保留 `days` 参数与返回结构；
3. 验收：456 项全绿 + 新增差分用例 + 浏览器 `/stock-flow`、`/market-flow` 数值不变；
4. 仍不碰 `_cached_get`（缓存独立拆分按规划放 S? 之后，避免一次动两层）。
