### 2.2 字段映射（交叉核对后的结论）

用同一天、同一只股票、返回**命名字段**的 `ulist.np` 响应做锚点：

| 列 | daykline | kline | 命名接口 | 含义 | 证据 |
|---|---|---|---|---|---|
| 1 | `2026-11-06` | 同 | — | 交易日 | 结构 |
| 2 | -318894480.0 | 同 | `f62` = -318894480.0 | 主力净额 | **强**：`f62 == f72 + f66` |
| 3 | -108674.0 | 同 | `f84` = -108674.0 | 小单净额 | 数值相等 + 约定 |
| 4 | 319003136.0 | 同 | `f78` = 319003136.0 | 中单净额 | 数值相等 + 约定 |
| 5 | -133286896.0 | 同 | `f72` = -133286896.0 | 大单净额 | **强**：与 f56 配对后满足 `f52=f55+f56` |
| 6 | -185607584.0 | 未请求 | `f66` = -185607584.0 | 超大单净额 | **强**：`f52 - f55` 精确等于它 |

恒等式（120 行全部成立）：

```
f52 == f55 + f56                  主力 = 大单 + 超大单        ✓（最大残差 0 元）
f52 + f53 + f54 ≈ 0               主力 + 中单 + 小单 ≈ 0      ✓（最大残差 168 元）
超大单 = f52 - f55（kline 缺 f56） = -185607584.0 = daykline f56 ✓
f69/f75/f81/f87 = -299/-215/515/0 → 合计 ≈ 0（百分比×100）      ✓
```

> ⚠ 不要把 5 列直接相加验证"资金守恒"：主力已含大单+超大单，相加等于重复计算
> （2026-05-14 那行会残留 3.8 亿）。正确式子是 `f52+f53+f54≈0`。

### 2.3 为什么是 PARTIAL 而不是 VERIFIED

已验证：报文结构、`klines` 分段数、单位（元）、日期格式、`f51/f52/f55/f56` 的数值与语义、
"kline 缺 f56 时用 `f52-f55` 反推"的算法、当日与历史两条接口同一天数值完全一致；
**列顺序为固定内部顺序**（换序请求证否"跟随 fields2"）；
**第二只股票（000001）与指数快照都复现同一套列对应**，不是茅台个例。

未独立证实：

1. **`f78` 与 `f84` 哪个是中单、哪个是小单**：数值分别等于第 4、3 列，但"第 3=小 / 第 4=中"依赖东财 f 字段约定，
   报文里没有字段名可自证。旁证：茅台单笔金额大，占比 5.15% vs 0.00% 与"中单有量、小单几乎为 0"相符，但这是推断。
2. ~~`fields2` 输出顺序是否跟随请求顺序~~ → **已用换序请求证否**（见 §2.5）：
   把 fields2 改成 `f51,f56,f55,f54,f53,f52`，返回**逐字不变**，仍是 日期,主力,小单,中单,大单,超大单。
   即列顺序是接口内部的固定顺序，与请求顺序无关。原先"位置=请求顺序"的假设是错的，
   列含义只能靠数值与命名字段对齐（§2.2）来确定 —— 这也让 §2.2 的结论更强，而不是更弱。

### 2.4 本轮核对顺带发现的既有口径问题（**已在单独 Hotfix 中修复，见 §2.6**）

1. **中单/小单取错字段（影响 `/market-flow` 页面数字）**
   `get_market_flow()` 用 `f69`（超大单**占比**）当"中单"、`f75`（大单**占比**）当"小单"；
   真正的中单/小单净额是 `f78` / `f84` —— 而这两个字段请求里**本来就已经带了**（`fields` 含 f78,f81,f84,f87）。
   实测 f69=-299、f75=-215，是百分比而非元。
2. **`val2yi()` 的单位启发式有缺陷**
   `round(v/1e8,2) if abs(v) > 1e6 else round(v,2)`：对 -299 这种百分比直接当"亿元"，
   对小额净流入（<100 万元）也按"元"取整，单位混用。S2 应统一成"源永远给元 → 一律 /1e8"。
3. **secid 映射不一致**（用户已确认一并放到 S2 统一处理）
   `_fflow_secid()` 把 6 和 9 开头都映射为沪市（`1.`），`get_stock_real_money_flow()` 只把 6 开头映射为沪市。
   9 开头（沪市 B 股）在后者会被当成深市，本次只记录。

前两条已由 hotfix 修复（§2.6，提交见 Git 记录）；第 3 条 secid 统一仍留到 S2 Provider 迁移时一起做。

## 3. 需要合并的重复点

1. `_fflow_secid()` 与 `get_stock_real_money_flow` 里的 `f"{'1' if 6/9 else '0'}.{code}"` —— 同一规则两处实现。
2. `yi()`（元→亿、`round 2`）在逐日与当日各写一遍。
3. `klines[0].split(",")` 的下标假设（`parts[1]=主力, parts[2]=小单, parts[3]=中单, parts[4]=大单, parts[5]=超大单`）出现两次。
4. 主力 = 大单 + 超大单 的校验收敛点不统一（一处直接取 `f52`，一处 `f52 - f55`）。
5. 三个函数各自 `requests.get(..., timeout=6/8/10)` —— 超时口径不一致。

## 4. Provider 设计

```
services/data/providers/eastmoney_flow.py

class EastMoneyFlowProvider(Provider):
    name = "eastmoney_flow"
    kind = "flow"
    timeout = 8.0

    # 逐日：stock/fflow/daykline
    def request(self, code, days=None, mode="history"): ...
    def normalize(self, raw, code=None, days=None, mode="history"):
        # 返回 (data, asof)
        # mode="history"  → {"dates":[…MM-DD], "flows":{…}, "unit":"亿元", "is_mock": False, "latest_date": "YYYY-MM-DD"}
        # mode="today"    → {"main_force":…, "super_large":…, "large":…, "middle":…, "small":…,
        #                    "asof_date": "YYYY-MM-DD"}
```

- 统一单位：内部一律**元**保存原始值，出口一次 `/1e8 + round(2)`；不在两处各转一次。
- 统一 secid：`normalizers.secid(code, sh_prefix="1", sz_prefix="0")`。
- `asof`：用 `klines[0][0]`（最近交易日）解析成 `YYYY-MM-DD`；拿不到就空串，不用今天顶替。
- `days` 限制：`lmt=0` 拉全量再切片（保持现有 `days` 语义），切片点固定在 normalize 内。
- 空 `klines` / 缺字段：`ProviderEmpty` / `ProviderFormatError`，不再靠 `if not text: return None` 吞掉原因。
- **不实现** `call_chain` 到"腾讯资金源"：目前没有真实第二资金源，双源降级只保留机制（已有测试），
  生产链条仍只有一根，**不得对外宣称已自动切换**。

## 5. 兼容约束（硬性）

1. `get_stock_money_flow(code, days=20)` 的签名、`Unit`、`is_mock`、`dates` 的 `MM-DD` 格式**不能变**。
2. `get_stock_real_money_flow(code)` 的 5 个金额 + 5 个占比字段名与含义**不能变**。
3. `get_market_flow()` 的 `main_force/super_large/large_order/middle_order/small_order/date/index_*`
   以及 `_flow_available` 语义**不能变**（S1 收尾新增的"零值 vs 没数据"判断依赖它）。
4. `_cached_get` 的缓存键（`stockflow_hist_<code>`）保持不变，否则线上缓存全部失效。
5. 页面字段（`/stock-flow`、估值页的资金块）一律不改。

## 8. 前端空值展示语义（方案 A：不做图例悬停 Tooltip）

`get_market_flow()` 在"源没给中单/小单金额"时返回 `null`（不是 0）。前端据此展示：

| 情况 | 展示行为 |
|---|---|
| 某类别为 `null` | 不绘制该扇区；`gapHint()` 动态点名缺失类别（如"中单数据暂缺，当前图表仅展示可用资金类别。"） |
| 四类全为 `null` | 不绘制任何扇区；显示"超大单、大单、中单、小单数据暂缺，暂无可用资金数据。" |
| 真实 0 | 正常绘制，tooltip 显示 `0.00亿` |
| 数据齐全 | 不插入提示节点（`putPieGapHint` 会把已有节点移除） |

职责划分：`format.js` 负责空值语义（`chartValue/pieItems/pieTip/gapHint`），
`app.js` 负责 ECharts 接线与 DOM 展示，提示文字由 `gapHint()` 动态生成、不写死。

**关于 tooltip 的边界（不要过度声明）**

- ECharts 不会为 `null` 数据绘制扇区，因此**不存在"悬停 null 扇区看 tooltip"这条路径**；
  缺失信息对用户的实际呈现只来自 `gapHint()`。
- `pieTip()` 的 `null → "暂无数据"` 是**防御性格式化**：保证即使被调用也不会显示 `0.00亿`，
  它不是一条浏览器可复现的交互保证。
- 不增加图例悬停 tooltip、不增加额外交互、不改饼图结构（方案 A）。

**状态不变**：`f53/f54` 中单/小单语义仍为 **PARTIAL**（无官方字段字典自证）；
`secid` 规则统一留给 S2；数据源统计持久化留给 D5。
