### 2.2 字段映射（交叉核对后的结论）

用同一天、同一只股票、返回**命名字段**的 `ulist.np` 响应做锚点：

| 列 | daykline | kline | 命名接口 | 含义 | 证据 |
|---|---|---|---|---|---|
| 1 | `2026-11-06` | 同 | — | 交易日 | 结构 |
| 2 | -318894480.0 | 同 | `f62` = -318894480.0 | 主力净额 | **强**：`f62 == f72 + f66` |
| 3 | -108674.0 | 同 | `f84` = -108674.0 | 小单净额 | 数值相等 + 约定 |
| 4 | 319003136.0 | 同 | `f78` = 319003136.0 | 中单净额 | 数值相等 + 约定 |
| 5 | -133286896.0 | 同 | `f72` = -133286896.0 | 大单净额 | **强**：与 f56 配对后满足 `f52=f55+f56` |
| 6 | -185607584.0 | 未请求 | `f66` = -185607584.0 | 超大单净额 | **强**：`f52 - f55` 精确等于它 |

恒等式（120 行全部成立）：

```
f52 == f55 + f56                  主力 = 大单 + 超大单        ✓（最大残差 0 元）
f52 + f53 + f54 ≈ 0               主力 + 中单 + 小单 ≈ 0      ✓（最大残差 168 元）
超大单 = f52 - f55（kline 缺 f56） = -185607584.0 = daykline f56 ✓
f69/f75/f81/f87 = -299/-215/515/0 → 合计 ≈ 0（百分比×100）      ✓
```

> ⚠ 不要把 5 列直接相加验证"资金守恒"：主力已含大单+超大单，相加等于重复计算
> （2026-05-14 那行会残留 3.8 亿）。正确式子是 `f52+f53+f54≈0`。

### 2.3 为什么是 PARTIAL 而不是 VERIFIED

已验证：报文结构、`klines` 分段数、单位（元）、日期格式、`f51/f52/f55/f56` 的数值与语义、
"kline 缺 f56 时用 `f52-f55` 反推"的算法、当日与历史两条接口同一天数值完全一致；
**列顺序为固定内部顺序**（换序请求证否"跟随 fields2"）；
**第二只股票（000001）与指数快照都复现同一套列对应**，不是茅台个例。

未独立证实：

1. **`f78` 与 `f84` 哪个是中单、哪个是小单**：数值分别等于第 4、3 列，但"第 3=小 / 第 4=中"依赖东财 f 字段约定，
   报文里没有字段名可自证。旁证：茅台单笔金额大，占比 5.15% vs 0.00% 与"中单有量、小单几乎为 0"相符，但这是推断。
2. ~~`fields2` 输出顺序是否跟随请求顺序~~ → **已用换序请求证否**（见 §2.5）：
   把 fields2 改成 `f51,f56,f55,f54,f53,f52`，返回**逐字不变**，仍是 日期,主力,小单,中单,大单,超大单。
   即列顺序是接口内部的固定顺序，与请求顺序无关。原先"位置=请求顺序"的假设是错的，
   列含义只能靠数值与命名字段对齐（§2.2）来确定 —— 这也让 §2.2 的结论更强，而不是更弱。

### 2.4 本轮核对顺带发现的既有口径问题（**已在单独 Hotfix 中修复，见 §2.6**）

1. **中单/小单取错字段（影响 `/market-flow` 页面数字）**
   `get_market_flow()` 用 `f69`（超大单**占比**）当"中单"、`f75`（大单**占比**）当"小单"；
   真正的中单/小单净额是 `f78` / `f84` —— 而这两个字段请求里**本来就已经带了**（`fields` 含 f78,f81,f84,f87）。
   实测 f69=-299、f75=-215，是百分比而非元。
2. **`val2yi()` 的单位启发式有缺陷**
   `round(v/1e8,2) if abs(v) > 1e6 else round(v,2)`：对 -299 这种百分比直接当"亿元"，
   对小额净流入（<100 万元）也按"元"取整，单位混用。S2 应统一成"源永远给元 → 一律 /1e8"。
3. **secid 映射不一致**（用户已确认一并放到 S2 统一处理）
   `_fflow_secid()` 把 6 和 9 开头都映射为沪市（`1.`），`get_stock_real_money_flow()` 只把 6 开头映射为沪市。
   9 开头（沪市 B 股）在后者会被当成深市，本次只记录。

前两条已由 hotfix 修复（§2.6，提交见 Git 记录）；第 3 条 secid 统一仍留到 S2 Provider 迁移时一起做。

## 4. Provider 设计

```
services/data/providers/eastmoney_flow.py

class EastMoneyFlowProvider(Provider):
    name = "eastmoney_flow"
    kind = "flow"
    timeout = 8.0

    # 逐日：stock/fflow/daykline
    def request(self, code, days=None, mode="history"): ...
    def normalize(self, raw, code=None, days=None, mode="history"):
        # 返回 (data, asof)
        # mode="history"  → {"dates":[…MM-DD], "flows":{…}, "unit":"亿元", "is_mock": False, "latest_date": "YYYY-MM-DD"}
        # mode="today"    → {"main_force":…, "super_large":…, "large":…, "middle":…, "small":…,
        #                    "asof_date": "YYYY-MM-DD"}
```

- 统一单位：内部一律**元**保存原始值，出口一次 `/1e8 + round(2)`；不在两处各转一次。
- 统一 secid：`normalizers.secid(code, sh_prefix="1", sz_prefix="0")`。
- `asof`：用 `klines[0][0]`（最近交易日）解析成 `YYYY-MM-DD`；拿不到就空串，不用今天顶替。
- `days` 限制：`lmt=0` 拉全量再切片（保持现有 `days` 语义），切片点固定在 normalize 内。
- 空 `klines` / 缺字段：`ProviderEmpty` / `ProviderFormatError`，不再靠 `if not text: return None` 吞掉原因。
- **不实现** `call_chain` 到"腾讯资金源"：目前没有真实第二资金源，双源降级只保留机制（已有测试），
  生产链条仍只有一根，**不得对外宣称已自动切换**。

### 4.5 secid 标准化（**已实现**：`services/data/normalizers.py::secid`）

**现状与问题**

- `services/data/normalizers.py` 只有 `market_prefix(code, sh_zero_index=True)`，返回 `"sh"/"sz"`，
  **没有 `secid()`** —— 本文件 §4 里引用的 `normalizers.secid()` 是待新增的设计，不是已有函数。
- `market_prefix()` 把 `000001` 默认当上证指数（`sh_zero_index=True`），个股场景必须显式传 `False`；
  默认值就是那处"指数与个股同码"的陷阱。
- `_fflow_secid()` 用 `6/9 → 1.`、其余 `0.`；`get_stock_real_money_flow()` 只把 `6` 当沪市 ——
  两处规则不一致（已确认并已统一：三个资金函数都经由 Provider 走 `normalizers.secid()`；
  `_fflow_secid()` 保留为薄委托（旧测试仍锁它的输出），不再自己判市场）。
  测试见 `tests/test_eastmoney_flow_provider.py::TestSecid`。

**设计：`services/data/normalizers.py::secid(code, kind="stock")`**

```python
def secid(code, kind="stock"):
    """A 股代码 → 东方财富 secid（"市场.代码"）。

    kind="stock"：按代码段判断市场；
    kind="index"：只认显式指数映射表，不做代码段推断（指数与个股会撞码）。
    无法确定 → ValueError，不静默回退到某个市场。
    """
```

| 代码段 | kind | secid | 说明 |
|---|---|---|---|
| 600/601/603/605/688/689 | stock | `1.xxxxxx` | 沪市 A（含科创板） |
| 900xxx | stock | `1.xxxxxx` | 沪市 B |
| 000/001/002/003/300/301 | stock | `0.xxxxxx` | 深市 A（含创业板） |
| 200xxx | stock | `0.xxxxxx` | 深市 B |
| 43xxxx / 83xxxx / 87xxxx / 88xxxx / 92xxxx | stock | `0.xxxxxx` | 北交所 |
| 其余 / 空 / 非 6 位数字 | stock | **raise ValueError** | 不猜市场 |
| 000001 | index | `1.000001` | 上证指数 |
| 399001 / 399006 / 399005 | index | `0.399xxx` | 深证成指 / 创业板指 / 中小板指 |
| 000300 / 000905 / 000016 / 000688 | index | `1.000xxx` | 沪深300 / 中证500 / 上证50 / 科创50 |
| 899050 | index | `0.899050` | 北证50 |
| index 表里没有的码 | index | **raise ValueError** | 指数必须显式登记 |

**关键约定**

1. `000001` 的语义**只能由 `kind` 决定**：`kind="index"` → `1.000001`；`kind="stock"` → `0.000001`。
   **禁止**用 `market_prefix()` 的默认参数去决定指数，否则会把平安银行和上证指数混成一个 secid。
2. 未知段（如 `700000`、`60051`、`abc`）**必须抛异常**，由调用方决定"跳过该标的"还是"整体失败"，
   不允许静默映射到 `0.` 或 `1.` —— 静默映射的后果是拿到另一个标的的数据而不报错。
3. 指数映射表放在模块常量里（`INDEX_SECIDS`），新增指数必须同时加校验用例。

### 4.6 Provider 的第三种模式：`market_snapshot`（ulist.np）

`get_market_flow()` 的大盘资金并不是 kline / daykline，而是 **`ulist.np` 的多标的快照**。
两者报文结构完全不同，必须作为独立模式，**不得把 `diff` 当 `klines` 解析**。

| 模式 | 接口 | 用途 | 返回结构 |
|---|---|---|---|
| `history` | `push2his .../fflow/daykline/get` | 个股近 N 日资金 | `klines`（CSV 字符串，每行 6 段） |
| `today` | `push2 .../fflow/kline/get` | 个股当日快照 | `klines`（CSV 字符串，每行 5 段；`lmt` 只认 1） |
| `market_snapshot` | `push2 .../ulist.np/get` | 大盘多指数资金 | `data.diff`（**JSON 对象数组**，每项含 `f62/f66/f72/f78/f84`） |

**请求参数（market_snapshot）**

```
GET https://push2.eastmoney.com/api/qt/ulist.np/get
  secids = ",".join(idx.secid)        # 例如 1.000001,0.399001
  fields = f62,f66,f72,f78,f84        # 金额（元）
           [,f69,f75,f81,f87]         # 占比(%)，只用于展示，绝不进入金额
```

**输入结构**

```python
[{"name": "上证指数", "secid": "1.000001"}, {"name": "深证成指", "secid": "0.399001"}]
```

**输出结构**

```python
{
  "indices": [
    {"name": "上证指数", "secid": "1.000001",
     "main_force": -202.34, "super_large": -90.11, "large_order": -112.23,
     "middle_order": 36.71, "small_order": 165.63,
     "partial": False}
  ],
  "total": {"main_force": -524.97, "super_large": -233.21, "large_order": -291.77,
            "middle_order": 45.83, "small_order": 479.15},
  "partial": False,
  "asof": ""
}
```

- **单位**：源给"元"，一律 `yuan_to_yi()`（`/1e8`，两位小数）；占比字段不转换、不进金额。
- **asof**：`ulist.np` **不返回任何时间戳**。Provider 的 `asof` 必须为空串，
  由组装层用腾讯指数快照的 `parts[30]`（`20261106161401`）填 —— **禁止用 `now()` 顶替**。
- **空数据**：`diff == []` 或 `data` 为 null → `ProviderEmpty`（不是"零值资金"）。
- **部分字段缺失**：某个指数缺 `f62/f66/f72` 中任一金额 → 该指数标 `invalid` 并从聚合剔除；
  只有 `f78/f84` 缺失 → 该指数 `partial=True`，聚合时这两项置 `None`（`total` 也置 `None`），
  前端由 `gapHint()` 提示，绝不补 0。
- **与腾讯并行组装**：两者用 `ThreadPoolExecutor` 各自独立报告结果，不互相掩盖：
  - 东财失败 + 腾讯成功 → 指数行情照常，资金字段 `None`，整体 `status="partial"`；
  - 东财成功 + 腾讯失败 → 资金可用，指数价格 `None`，页面不显示"0.00"；
  - 两者皆失败 → `None`（页面"暂无数据"）。
- **禁止**：把 `diff` 的 `f62` 之类当成 `klines[0].split(",")[1]`；把 `f69/f75`（占比）当金额；

## 8. 前端空值展示语义（方案 A：不做图例悬停 Tooltip）

`get_market_flow()` 在"源没给中单/小单金额"时返回 `null`（不是 0）。前端据此展示：

| 情况 | 展示行为 |
|---|---|
| 某类别为 `null` | 不绘制该扇区；`gapHint()` 动态点名缺失类别（如"中单数据暂缺，当前图表仅展示可用资金类别。"） |
| 四类全为 `null` | 不绘制任何扇区；显示"超大单、大单、中单、小单数据暂缺，暂无可用资金数据。" |
| 真实 0 | 正常绘制，tooltip 显示 `0.00亿` |
| 数据齐全 | 不插入提示节点（`putPieGapHint` 会把已有节点移除） |

职责划分：`format.js` 负责空值语义（`chartValue/pieItems/pieTip/gapHint`），
`app.js` 负责 ECharts 接线与 DOM 展示，提示文字由 `gapHint()` 动态生成、不写死。

**关于 tooltip 的边界（不要过度声明）**

- ECharts 不会为 `null` 数据绘制扇区，因此**不存在"悬停 null 扇区看 tooltip"这条路径**；
  缺失信息对用户的实际呈现只来自 `gapHint()`。
- `pieTip()` 的 `null → "暂无数据"` 是**防御性格式化**：保证即使被调用也不会显示 `0.00亿`，
  它不是一条浏览器可复现的交互保证。
- 不增加图例悬停 tooltip、不增加额外交互、不改饼图结构（方案 A）。

**状态不变**：`f53/f54` 中单/小单语义仍为 **PARTIAL**（无官方字段字典自证）；
`secid` 规则统一留给 S2；数据源统计持久化留给 D5。
